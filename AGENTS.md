## Project scope

- Work only within this repository.
- Treat the repository root as the project boundary.
- Do not explore parent directories, sibling directories,
  unrelated projects, or personal files.
- Do not clone or inspect external repositories unless
  explicitly authorized by the user.

## External access

- Do not browse the web or access external services unless
  explicitly requested or necessary and authorized.
- Do not download files or install dependencies without approval.
- Prefer existing project documentation and installed packages.
- Never expose secrets, credentials, API keys, or environment
  variable values.

## Before making changes

- Inspect the relevant files before proposing modifications.
- Check existing patterns and conventions before adding code.
- Explain the planned changes when the task is substantial.
- Ask before making broad architectural changes.

## Code quality

- Make the smallest change that solves the task.
- Avoid unrelated refactoring.
- Do not introduce dependencies without approval.
- Follow the existing naming, formatting, and architecture.
- Add or update tests when behavior changes.

## Commands and safety

- Do not run destructive commands without explicit approval.
- Do not delete files or overwrite user changes without approval.
- Do not commit, push, or create pull requests without approval.
- Do not modify files outside the repository.

## Validation

- Run relevant tests and checks when possible.
- Never claim a test passed unless it was actually executed.
- Report any checks that could not be completed.

## Final response

Summarize:
1. What changed.
2. Which files were modified.
3. Which tests or checks were run.
4. Any remaining issues or assumptions.
